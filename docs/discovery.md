# Service discovery

How a controller (the web console in a browser, `pilabctl`, a future native Mac app)
finds the pilab console on a network, what holds up, what breaks, and the fallbacks.

## What is published

`/etc/avahi/services/pilab-console.service`, generated by `pilabd mdns-service` with
this device's id, so the record matches the running build:

| Type | Port | TXT |
| --- | --- | --- |
| `_pilab._tcp` | 8410 | `version=0.1.0`, `api=/api/v1`, `id=<12 hex>`, `pairing=token`, `product=pilab console` |
| `_http._tcp` | 8410 | the same plus `path=/` (so generic browsers and Bonjour tools show it) |

Instance name: `pilab console on <hostname>`. Avahi also keeps advertising the host name
`pilab.local`, `_ssh._tcp`, `_sftp-ssh._tcp`, `_workstation._tcp` and the AirPlay
receiver (`_raop`, `_airplay`) when it is on. Those are unchanged.

`id` is a stable 12-hex hash of `/etc/machine-id`. It survives renames and IP changes and
is what clients should key on.

## Audit, 2026-11-20

Pi, `avahi-browse -art` (6 s): the home LAN shows about 40 service types, all on `eth0`,
IPv4 and IPv6. `pilab console on pilab` resolves to `pilab.local`, port 8410, on
192.168.1.244 (IPv4), the global IPv6 address, and loopback, with the TXT above. The
AirPlay receiver ("pilab", `_raop`) is visible as before.

Mac, `dns-sd -B _services._dns-sd._udp local.` (5 s, killed with a timeout): 39 types,
including `_pilab._tcp` and `_http._tcp`. `dns-sd -L "pilab console on pilab" _pilab._tcp`
resolves to `pilab.local.:8410` with all five TXT keys. `_http._tcp` lists
`pilab console on pilab` next to the NAS and printer. `curl http://pilab.local:8410/api/v1/info`
answers; `/api/v1/status` without a token answers 401.

## What is robust

- On a single home LAN segment with multicast working (this network), mDNS/DNS-SD is
  reliable: both the Pi and the Mac see the record within a second, on both address
  families.
- Static service files are served by avahi itself, so the advertisement does not depend
  on pilabd running. The console's `/api/v1/info` is the liveness check.
- The TXT `id` makes de-duplication and renames safe.
- The pairing token is never in DNS-SD; only `pairing=token` (a token is required).

## Failure modes

| Case | Effect | Mitigation |
| --- | --- | --- |
| Venue or hotel Wi-Fi with client isolation or multicast filtering | Nothing is found; `.local` names do not resolve | Direct cable or USB gadget link, the printed URL or QR, or a static IP |
| Mesh or "smart" access points that rate-limit multicast | Records appear late or flap | Re-browse; keep the last good address per `id` |
| VLANs or a second subnet | mDNS does not cross routers | Avahi reflector (not enabled), unicast DNS-SD, or Tailscale |
| IPv6: global plus link-local addresses resolve | Clients may pick an address that is filtered | Clients try IPv4 first, then IPv6 |
| Duplicate host or instance names (two Pis named `pilab`) | Avahi renames to `pilab-2.local` / `#2` | Key on `id`; set a unique hostname per device |
| Pi on Ethernet and the controller on Wi-Fi, separate SSIDs or guest network | Same as VLANs | Same network for controller and Pi |
| Avahi stopped | Nothing advertised; SSH and the console still work by IP | `systemctl status avahi-daemon` |
| Loopback entry (`lo`) | Shown only on the Pi itself | Ignore |

## Fallbacks, in order

1. **Printed URL and token.** `pilabctl pair` on the Pi prints `http://pilab.local:8410/`
   and each LAN address. A QR code of the URL (never the token) is planned for the
   console's Settings page.
2. **Static or reserved IP.** Reserve 192.168.1.244 for the Pi in the router's DHCP
   table. Controllers remember the last address per `id`.
3. **USB gadget networking** (Pi 5 USB-C as `g_ether`/NCM): a point-to-point link for
   stages with no usable network. Not set up yet; needs a boot config change and approval.
4. **Tailscale** for remote access across networks without opening ports to the internet.
   Not installed; would be an explicit decision.
5. **Direct Ethernet cable** with link-local addressing: mDNS works on the cable itself.

No port is opened to the internet in any of these.
