## Reading the vulnerability reports

- Matches are de-duplicated by (source package, CVE): one source package that builds twenty
  binaries counts once.
- *Fix in the archive* means a newer Debian package already fixes it: `apt upgrade` clears it
  (or a rebuild of the image).
- *No fix yet* and *Will not fix* are Debian's own security-tracker states. Many "will not fix"
  entries are minor issues in packages the image does not run.
- The kernel is shown apart: Debian's tracker follows its own 6.12 kernel, not the Raspberry Pi
  6.18 RT kernel, so those matches are leads to check against the Raspberry Pi kernel changelog,
  not findings.
- Grype's matching needs the source version of each package; the generator records it
  (`upstream=name@version` in the package URL). Without it Debian binaries built from a
  differently versioned source (libldb from samba) match the wrong advisories.

## CI note

The generator needs no secrets and no network except the scanners' own database or API.
A GitHub Actions job on `ubuntu-24.04-arm` would be:

```yaml
- uses: dtolnay/rust-toolchain@stable
- run: cargo install cargo-cyclonedx --locked
- run: |
    curl -sSfL https://raw.githubusercontent.com/anchore/grype/main/install.sh | sh -s -- -b "$HOME/.local/bin"
    curl -sSfL -o "$HOME/.local/bin/osv-scanner" https://github.com/google/osv-scanner/releases/latest/download/osv-scanner_linux_arm64 && chmod +x "$HOME/.local/bin/osv-scanner"
- run: tools/sbom.sh --image-sbom build-meta/filesystem-*.sbom.zst --image-version "$VERSION"
- uses: actions/upload-artifact@v4
  with: { name: sbom, path: sbom/ }
```

Fail the job when the Rust scan reports anything, and when the image scan shows a Critical
with a fix in the archive. Pin the install scripts to a commit before relying on this.
No workflow is committed yet.
